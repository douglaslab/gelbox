# Image orientation fixes and measured codec boundaries

The initial 16 native fixtures are imported through actual drop handling in the compiled web app. Browser ImageBitmap results are measured by raw GL texture readback, avoiding 2D canvas color conversion. Instrumentation observes the returned bitmap and returns that same object to the application. Both Chromium rendering backends, Firefox132 and WebKit18.2 are covered.

**Bugs reproduced and fixed:** Chromium ignored `imageOrientation:none` for oriented JPEGs, mirroring/rotating images and swapping dimensions for orientations5–8. WebKit also rotated PNG eXIf orientation6. The production decoder now removes JPEG EXIF APP1 segments and PNG eXIf chunks before decoding. Compressed pixels, ICC/color data and unrelated metadata are preserved byte-for-byte; no image resampling occurs. Unit tests verify those invariants, all JPEG orientations, malformed/truncated boundaries and unchanged non-EXIF inputs. Format acceptance remains native's lowercase .jpg/.png/.gif list, independent of MIME.

**Measured scope:** all dimensions and orientations match. Chromium/Firefox PNG and GIF decoded bytes match exactly. WebKit opaque PNG/GIF and JPEG match exactly. Chromium/Firefox JPEG has maximum channel error1 (240 differing channels in the base image). WebKit alpha PNG discards RGB at alpha0 and rounds visible straight RGB by at most1; the fixture's premultiplied pixels match exactly. Reports retain raw, visible and premultiplied errors separately. JPEG's ≤1 assertion bounds the observed codec difference; it is not an accepted exact-parity waiver. WebKit transparency still needs visible filtered/composed native replay before broader visual equivalence is claimed.

Fresh verification: 2,986 units /73 files,44 production cases (including216 native RGB comparisons),14 Firefox/WebKit compatibility cases,60 affected image workflow cases. All listed gates include both orientation fixes. Source/build hashes are retained. Shipping Safari, original-native visible codec replay, wide-gamut/CMYK boundaries and complete W06 remain open. The locally prepared website release is intentionally unchanged for review.

The [wide-gamut extension](wide-gamut/README.md) adds five fixtures (21 total) and measures Display P3/Adobe RGB decoded pixels on all four backend/engine combinations. CMYK acceptance is separately aligned with native; these additions do not close original-release visible replay or filtered-alpha composition.
